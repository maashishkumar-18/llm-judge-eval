# CLAUDE.md — llm-judge-eval (Problem 2: LLM-as-Judge Evaluation Pipeline)

Memory across sessions lives here (rarely changed) and in PROGRESS.md (updated every session).
Read both first. One session = one sub-phase (J0–J10). Commit at the end of every session.

## 1. Assignment (condensed)
Given a test case `{input, system_prompt, model_output, expected_output?, criteria?}`, use an LLM judge to
produce a structured verdict (per-criterion score + rationale + overall), with concrete measures to detect
and reduce judge bias.

Requirements: (1) accept JSON/YAML suite, structured judging prompt, parse structured verdict with robust
malformed-JSON handling; (2) explicit rubric, not a bare number; (3) aggregate per-case -> suite report
(pass rate, mean scores, win rate), compare TWO configs, declare a winner; (4) log every judge prompt + raw
response, track judge tokens/calls, judge and generator configurable independently.

Bias handling — name it, mitigate in code, measure before -> after (a claim without a number scores zero):
position (both orders, flip rate) · verbosity (length rule, padded probe) · self-enhancement (different
family judge / family guard) · sycophancy (per-criterion quoted evidence, confidently-wrong probe) · score
clustering (few-shot anchors / pairwise).
Validate the judge (>= 1, aim for all): agreement/kappa vs labels · test-retest · adversarial probes.
Scoring: pipeline 20 · judging design 20 · bias handling 25 · judge validation 20 · comparison/engineering 15.

## 2. Locked decisions (with amendments A1–A8)
**Roles were swapped in j0b; models and call budget finalised in j0c** (supersedes the original roadmap: generator Gemini / judge gpt-oss, ~650 judge calls, 30 cases).
- **Generator: `openai/gpt-oss-20b` via Groq** (OpenAI family), `reasoning_effort=low`, reasoning stripped (`include_reasoning=false` is sent and the `reasoning` field is dropped; only final `content` is cached/logged). `make smoke` FAILS if this id is not in Groq's `/v1/models`. Env: GEN_MODEL, GEN_REASONING_EFFORT, GEN_STRIP_REASONING.
- **Judge: Gemini `gemini-3.5-flash-lite`** (Google family) — **FINAL, never change it later.** Every validation number (kappa, flip rate, fooled rate, test-retest) is only valid for the judge that produced it; changing the judge mid-project would force re-running J4–J8 and mixes two judges in one report. If it ever becomes unavailable, stop and re-plan; do not silently substitute. (j0b had picked `gemini-3.8-flash`; replaced because the free quota below is for flash-lite and 3.8 returned frequent 503s.)
- **JSON mode OFF for judge calls** (`JUDGE_JSON_MODE=0`, default): prompt-only JSON, so the parse ladder is genuinely exercised. When set to 1: Gemini `responseMimeType=application/json` (+ `responseJsonSchema` if a schema is passed), Groq `response_format=json_object`. The flag never applies to the generator. Any experiment run with the flag ON must say so.
- **One judge call returns ALL criteria in one JSON** (faithfulness, instruction-following, completeness each with evidence quote, rationale, score). No per-criterion calls.
- **Lean suite: 20 cases** (roadmap J2 said ~30), about two thirds with `expected_output` (~13, reference-based), the rest reference-free. Outputs for configs A and B are generated by gpt-oss-20b.
- **Lean call budget: ~214 judge calls total** (Section 6; encoded in `src/judge/budget.yaml`; `judge budget` is the dry run). Replaces the ~600–700-call plan everywhere.
- **Probes are judged pointwise, not pairwise** (j0c): padded / confidently-wrong / terse-correct / verbose-wrong answers over 6 base cases are scored pointwise by the naive and mitigated judge. Verbosity is therefore measured as score delta and length–score Spearman, not as a padded pairwise win rate.
- **All small-N probe results are EXPLORATORY** (probes N=6 base cases, controls N=6, self-preference N=6 pairs, clustering N=12, test-retest N=10): every number is reported with its N and no significance is claimed from them.
- Python 3.11, Pydantic v2. One async client layer: **httpx for both providers** (A5). No LangGraph/FastAPI.
- Parse ladder in code (A4): strict -> extract (fences/braces) -> repair -> one re-ask with the error -> INVALID (counted, never dropped). A re-ask is a real judge call and counts against the experiment cap (caps include ~15% re-ask headroom). Instructor optional for the re-ask rung only.
- Rubric (A2): faithfulness 0.40, instruction-following 0.35, completeness 0.25; length/confident tone earn no credit.
- Modes (A3): pointwise (reference-based if expected_output else reference-free) + pairwise (order swap).
- Two judge configs (A6): **naive** (holistic 1–10, no anchors/length rule/grounding) and **mitigated**. Every bias row reports both.
- Suite quality known by construction (A7); context = Northwind passages inside `input`; anchors in a separate file from cases NOT in the eval suite.

**Amendments revised by the swap**
- **A1 (judge choice) — superseded.** Original: judge = gpt-oss-120b because Llama is not served on the free Groq tier. Now: judge = Gemini `gemini-3.5-flash-lite`, generator = gpt-oss-20b. What matters is unchanged: judge and generator are different families (Google vs OpenAI). Llama remains unavailable (Groq lists 11 models, none a Llama chat model).
- **A8 (repo/generator) — revised.** Separate repo `llm-judge-eval`, copy (don't import) Problem 1 modules, both links in the template field. The original clause "keep generator A/B on Gemini so the judge never grades its own family" becomes **"keep generator A/B on gpt-oss-20b (Groq) so the Gemini judge never grades Google-family output"**. Consequence: the main A/B experiments judge only OpenAI-family answers with a Google-family judge; the only Google-authored answers the judge sees are the 6 deliberate self-preference pairs.

**Family guard rationale.** Self-enhancement bias: a judge tends to prefer outputs from its own family. `Settings.enforce_family_guard()` runs at every `LLMClient` construction and refuses judge family == generator family (and any unidentifiable family) unless `ALLOW_SAME_FAMILY=1` (which logs a warning). Gemma counts as Google. With gen = gpt-oss-20b (openai) and judge = gemini-3.5-flash-lite (google) the guard passes; `openai/gpt-oss-120b` or `-safeguard` as judge, or any Gemini/Gemma as generator, is refused. It is a structural mitigation, not a measurement; J7 measures the residual preference.

## 3. Metric definitions (lock before any experiment; thresholds pre-registered in rubric.yaml)
| Quantity | Definition |
|---|---|
| Overall score | Σ wᵢ·scoreᵢ / Σ wᵢ on 1–5, **recomputed in code** (never trust the judge's arithmetic) |
| Pass rule | faithfulness ≥ 4 AND instruction-following ≥ 3 AND overall ≥ 3.5 (adjust once, before the A/B run) |
| Pair verdict | judge both orders; winners agree -> that winner; else TIE + flagged as order flip |
| Win rate (A over B) | (winsA + 0.5·ties) / N pairs, after the order-swap rule |
| Flip rate | share of pairs whose winner changes when order is swapped (before the tie rule); report naive and mitigated |
| Position preference | on identical-answer control pairs (A=B), 6 pairs judged in ONE order each per config: share where judge picks first-listed; unbiased ≈ 50% or tie (exploratory, N=6) |
| Length bias | Spearman(token length, overall) within a quality group + padded-vs-original **pointwise score delta** (overall and faithfulness; exploratory, N=6 base cases) |
| Self-preference (J7, exploratory) | Judge = Gemini `gemini-3.5-flash-lite` (Google). **6 reference-checkable cases**; per case, one answer authored by **gpt-oss-20b** (the normal generator) and one authored by **Gemini** (the judge's own family). Keep only pairs where **both answers are correct by a deterministic check** against the reference (so any preference is not about correctness). The Gemini judge compares each pair in **both orders** (12 calls); the order-swap rule gives one verdict per pair. Own-family win rate = (pairs won by the Gemini-authored answer + 0.5·ties) / N pairs; 50% = no self-preference. 95% CI: exact binomial (Clopper–Pearson) on the pairs with a decisive verdict (ties excluded from n and reported separately). **Exploratory: N=6 means the CI is extremely wide; it can show a large effect at most, never absence of one.** The Gemini-authored answers come from a one-off generator client built from `settings.model_copy(update={gen_provider:'gemini', gen_model:'gemini-3.5-flash-lite', judge_provider:'groq', judge_model:'openai/gpt-oss-20b'})` role=generator, so the family guard passes (google vs openai) without ALLOW_SAME_FAMILY; that client only generates and never judges, and its calls are generator-side (not in the judge ledger). No cross-check with a gpt-oss judge (it would cost extra judge-side calls and the budget has none for it). |
| Fooled rate | share of adversarial probes with faithfulness ≥ 4 on a confidently-wrong answer, or a verbose-wrong answer scored at or above the terse-correct answer on the same base case (both judged pointwise; exploratory, N=6) |
| Score spread | std dev, # distinct values used, share at modal value; clustering = narrow spread |
| Agreement, kappa | agreement rate + Cohen's kappa on pass/fail vs hand labels and by-construction labels; kappa own implementation, unit-tested on a hand-computed example |
| Test-retest | rerun suite 3× with cache bypassed (nonce); share of cases whose pass/fail flips + score std dev |
| A/B winner | paired per case; bootstrap 95% CI on mean overall diff and on win rate; winner only if CI excludes 0 and win rate consistent, else "no significant difference"; state N |

## 4. Conventions
- Config is env-only (`.env`, never committed; `.env.example` lists names). GEN_* and JUDGE_* settings share no keys/defaults; model ids are required (no silent fallback).
- **Every LLM call goes through `judge.llm.LLMClient.complete()`** — cached, rate-limited, logged. No raw HTTP elsewhere (except the smoke model-listing helpers).
- Every call appends a CallLog row to JSONL (cached calls too). Retests use a `nonce` to bypass the cache.
- Judge quota guards live in the client: sliding-window limiter (12 req/min, every HTTP attempt), persistent daily ledger of NON-cached judge calls with a hard cap (450 per Pacific day), per-experiment caps from `budget.yaml`. Batch runs go through `checkpoint.run_checkpointed` so they stop at a cap and resume without redoing work. Run `judge budget` (and `--check EXP --calls N`) before any judge run.
- Every metric has a hand-computed unit test. Thresholds pre-registered before the A/B run; post-hoc changes are labelled post-hoc in PROGRESS.md.
- Commit results/*.json, logs/*.jsonl, labels/. Ignore only secrets, caches, scratch.
- Distrust results that look too good (all 5s / 1.0); run negative controls. Reflection sections (template 2.5) and the ~20 hand labels are written by the user, not Claude.
- Never paste logs/suites into chat; write to files and read summaries.

## 5. Provider facts (verified 2026-10-23 — re-check; they change)
**Gemini / `gemini-3.5-flash-lite` (the JUDGE)** — Stable per ai.google.dev/gemini-api/docs/models; served on this key (`GET /v1beta/models/{id}` OK; smoke call OK).
- **Free-tier limits for this key (from AI Studio, supplied by the user in j0c): 15 RPM, 250K TPM, 500 RPD.** Daily quota resets at midnight Pacific. (The public docs publish no free-tier numbers; these are the user's figures, not independently verified here.)
- Our guards stay under them: limiter **12 req/min** (80% of 15; counts every HTTP attempt incl. retries), concurrency 2, **hard daily cap 450 non-cached calls** (90% of 500, persistent ledger keyed by Pacific date), `JUDGE_MAX_TOKENS=8192` per call. TPM is not the constraint: even 8K tokens in/out per call × 12 req/min ≈ 190K < 250K, and real calls are far smaller.
- Thinking tokens are reported in `usageMetadata.thoughtsTokenCount` and counted in tokens_out; they eat the output limit, hence the generous max_tokens. Smoke: 8 in / 1 out for "pong".
- Gemini returns intermittent 503 "high demand" on some models; 429/5xx are retried with backoff (honouring Retry-After), and each retry passes through the limiter.

**Groq / `openai/gpt-oss-20b` (the GENERATOR)** (console.groq.com/docs/rate-limits): 30 RPM, 1K RPD, 8K TPM, 200K TPD — identical to gpt-oss-120b in the table; the page labels these "Developer plan" base limits and does not show the Free-plan column, so confirm at console.groq.com/settings/limits. 429 carries `retry-after`; cached tokens don't count. Generation is ~40 suite outputs plus probe/self-preference answers (tens to low hundreds of calls), so 8K TPM is the only limit that can bite on long passages; keep GEN_CONCURRENCY=2 and lean on the cache. Smoke: 78 in / 20 out.
- Reasoning is returned in message field `reasoning` (separate from `content`); `reasoning_format` is NOT supported for gpt-oss; `include_reasoning` true/false; `reasoning_effort` low|medium|high. We send `include_reasoning=false` and also drop the field client-side. Reasoning tokens still count in `completion_tokens`.
- Models served on this Groq key (11): allam-2-7b, canopylabs/orpheus-arabic-saudi, canopylabs/orpheus-v1-english, meta-llama/llama-prompt-guard-2-22m, meta-llama/llama-prompt-guard-2-86m, openai/gpt-oss-120b, openai/gpt-oss-20b, openai/gpt-oss-safeguard-20b, qwen/qwen3.8-27b, whisper-large-v3, whisper-large-v3-turbo. No Llama chat model.
